Scroll is the timeline.

Every scroll-animation library runs JavaScript sixty times a second to learn something the browser already knew. Dolly asks CSS instead. Everything that moves on this page was moved by the library — and nothing here runs JavaScript, including the counter above, which is reading your scroll in CSS.

What it refuses to do.

"tilt-up"

It never hides your content.

Every other library in this category puts opacity: 0 in a base rule and reveals it from script. When the script fails, is blocked, or the browser lacks support, the page is blank. Dolly puts the hidden state only in @keyframes, so no support means didn't animate, never didn't appear.

It has no runtime to fail.

No IntersectionObserver, no scroll listener, no rAF loop, no init call, no provider, no hydration. Nothing runs, so nothing runs late.

Reduced motion is a real path.

Under prefers-reduced-motion every move switches off and the page renders exactly as authored, because the authored state was never the hidden one.

Firefox is fine, today.

Scroll timelines run in Chrome 115+, Edge, Safari 26+ and Opera, about 87% of the web, with Firefox landing in 159. Everyone else reads a complete, still page. There is no shim to ship.

The entire API.

one attribute

Link the stylesheet, then annotate markup you already have. No init call, no wrapper component, no configuration object, because nothing is running that could read one.

<link rel="stylesheet" href="dolly.css">

<h1 data-dolly="tilt-up">Arrives as you reach it</h1>
<img data-dolly="rack" src="still.jpg" alt="">
<div data-dolly="progress" class="reading-bar"></div>

/* one caveat worth knowing: a parent with overflow:hidden becomes its
   own scroll container and pins the move. Use overflow:clip. */
